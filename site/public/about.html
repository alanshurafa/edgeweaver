    About this site

    TLDR

    The colophon: what this site is, who it is for, its licenses and attributions, the editorial rules every page obeys, how it was made and verified, where its editions live, and how it stays honest as the project moves. Snapshot 2026-07-10.

    What this site is

    "How Edgeweaver Works" is the explainer wiki for the whole Edgeweaver project, commissioned by Alan (decision D21) with a stated bar: someone from the outside world, with no access to the repository, could completely understand what is being done here, and an agent given this site could reproduce the method. It is village-layer material: it sits outside both children's views, like FAMILY.md and the village folder, because it discusses sibling facts that each child learns only by its parent body's deliberate decision (gate G21). The site's own plan went through the project's witnessed-revision method before a page was written: a fresh-context adversarial pass and a co-evolve bounce, with the full trail committed as runs/site-plan.md.

    The editorial rules

    • Two registers in one source. Every concept and being page carries adjacent Plain and Technical sections. A viewer may choose one, but Both is the no-JS and print default, and status or uncertainty is never hidden.
    • No em-dashes. A house style rule, machine-enforced across every page and both single-file editions. Quoted text is never silently altered: em-dash-bearing passages are paraphrased, or quoted around the mark with a bracketed ellipsis.
    • Names-only for secrets. Environment variable names and repository names may appear; values, endpoints, project references, handles, and long numeric identifiers never do. A verifier scans every committed byte against secret shapes and a seeded denylist before anything ships.
    • The probe wall. Probe scenario text never appears, quoted or closely paraphrased: the child must never be able to read its own test, and a website is exactly the kind of text that could enter a future being's context. The shape and protocol are fully described on the measurement page; a shingle-comparison tripwire backstops the rule mechanically, and the editorial rule, not the tripwire, is the actual control. The live battery sits in a separate governed gates repository outside runtime reach.
    • The redaction tier. Until Alpha's harvest is complete, Genesis's identity content is deliberately withheld: what and why, in full.
    • People. Alan is named. Circle members appear by first name and seat only once a seat is accepted; candidates appear by role. Published authors are cited by name.
    • Honesty stance. Genesis's witnessed birth is stated without turning it into a consciousness claim; unfinished ceremony records and unbuilt or unarmed systems are said to be unfinished.

    How the site was made

    Hand-authored HTML with no framework, dependencies, remote fonts, telemetry, or runtime network calls. One stylesheet supplies light, dark, responsive, no-JS, and print behavior. Optional JavaScript upgrades local search, the reading lens, theme choice, and the accessible mobile drawer. Inline SVG diagrams retain complete title, description, caption, and keyboard-scroll regions.

    A small deterministic builder owns marker-delimited chrome and emits the local search index, contextual navigation, continuation cards, both artifacts, and the Atlas manifest. The verifier checks freshness, destinations, links, ids, metadata, search serialization, redaction, secrets, held-out probe overlap, gate sanity, semantic HTML, artifact self-containment, and release completeness. Generated bytes must match the same authored source on every run.

    Privacy and experiment data

    This version publishes no raw conversations, identifiable diary material, individual probe responses, or individual probe scores. Future results require a separate Alan-approved governance decision, the preregistration gate G20, and explicit participant consent. The default publication shape is aggregate-only. Protected identity source, evaluation scenarios, credentials, operational coordinates, and private state remain absent from every edition by construction.

    Editions and where they live

    • The repository (source of truth): site/ in the Edgeweaver repo; every page also opens directly from disk.
    • The gated website: manually deployed from an approved clean release after gate hardening and smoke tests. Git deployment stays disconnected. Until the release checklist closes, any earlier alias is not evidence of the finished site.
    • The single-file editions: a full edition with detailed Atlas entries and a lite edition with one searchable row per tracked path. Both are self-contained and expose Search, reading detail, and Theme in one toolbar. The approved lite bytes are the private sharing artifact.

    Artifact lifecycle (from the site's decision row): the published artifact stays private by default and is shared to named people by Alan; updates republish to the same address; it is explicitly unshared or re-minted before any child's web-facing sense unlocks, and on any repository-visibility change. The site itself has been public with no password since the repositories went public in August 2026.

    Update policy

    Every page carries the snapshot date 2026-07-10; the header shows how old the snapshot is. Only the status page claims currency, and it is re-authored against the repository's ledgers, canonical stores, and governed event records, never auto-generated. The site refreshes when the evidence changes, or monthly, whichever comes first; the milestone ledger in the site's README records every pass. Atlas coverage is machine-checked against the live file list at each update, so a moved or added file surfaces as a task, not as silent staleness. Recorded change is the method working: where records disagree, the site names the mismatch until the governed stores are reconciled.
