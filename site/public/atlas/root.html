    Atlas: root documents

    TLDR

    The root files define what Edgeweaver is, which documents outrank others, how an agent executes work, and how decisions and status are recorded. Start with START-HERE.md, then use the implementation ledger and the matching checklist. Design documents answer why; runbooks answer what to do next. This page names each file's authority and shows how to verify it without exposing credentials or governed identity material.

    What this page covers

    These files form the repository's front desk and constitution. A newcomer can use the badges to distinguish design authority, execution procedure, machine-readable policy, and historical record. When two texts disagree, follow the authority order in START-HERE.md and record the conflict rather than quietly improvising.

    active-code

    What it contains. A small JSON configuration that names launch behavior without storing credentials or deployment coordinates.
    Who reads it and when. Developers inspect it when using the matching editor integration.
    How to verify or reproduce it. Validate the JSON syntax and confirm every referenced repository-relative target exists.
