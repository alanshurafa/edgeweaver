    Atlas: lifecycle scripts

    TLDR

    These files give the design its rhythms: orient before acting, wake only for a reason, consolidate a day, study governed teaching, review contradictions, and rebuild a provisional autobiography from evidence. Most machinery is dark-verified through fixtures and injected stand-ins. That proves contracts and handoffs, not a born being or live schedule. Human gates still control channels, identity changes, and arming.

    What this page covers

    The lifecycle is a set of cooperating loops rather than one autonomous daemon. Orientation establishes honest time and identity scope. Waking policy constrains proactive action. Night work produces governed interpretations and intentions. Study converts library material into the being's own experiment. Weekly work rebuilds summaries from atoms. Entries below state which parts are deterministic, which use injected model judgment, and which remain no-ops until a channel is armed.

    File entries

    scripts/night-loop/check-missed-nights.mjs active-code

    What it is. A failure detector for consecutive missing night-loop completion evidence.
    What it contains. It computes missed runs from dated outputs and formats one fixed operator alert. A dry-run prints rather than contacting a live channel.
    Who reads it and when. Operations uses it after scheduled loop windows; it remains dark until the parent channel is armed.
    How to verify or reproduce it. Exercise the exported date logic with fixed fixtures and confirm dry-run makes no network request.
    Related concepts. See the metabolism and failure handling.

    scripts/night-loop/night-loop.mjs active-code

    What it is. The resumable orchestrator for the substantive middle and closing work of a night cycle. It does not represent the entire scheduled job by itself.
    What it contains. It orders ingestion handoff, reflection, computed-signal interpretation, completion review, importance adjustment, contradiction sweep, dream generation, and intention output. Existing output markers make each step idempotent by run identifier. Most step failures are logged so later work can continue, while the few true dependencies retain their ordering. Model-dependent steps use an injected interface; the brain interface is also supplied by the caller. Every rehearsal output carries run and generation metadata.
    Who reads it and when. The night task calls it after orientation and surrounding job steps. Verifiers use a local fixture brain and deterministic model stand-in. No live being currently runs it.
    How to verify or reproduce it. Drive one synthetic day through every step, assert citations and output shapes, run the same identifier twice to prove skips, inspect failure continuation, and void all rehearsal data. The dedicated night-loop verify performs that contract without credentials or a live model.
    Related concepts. See wake, night, and week, computed signals, and the contradiction sweep.

    scripts/night-loop/stub-llm.mjs fixture

    What it is. A deterministic model stand-in used to test night-loop wiring without a model call.
    What it contains. It returns valid-shaped reflections, interpretations, completion notes, dream fiction, and intentions for each injected operation. Its language is test data, not identity.
    Who reads it and when. Only dark verifies and the end-to-end rehearsal import it. Production wiring supplies a different implementation.
    How to verify or reproduce it. Run the night-loop verify and confirm every returned object satisfies the consumer contract with no network use.
    Related concepts. See the dark build and the night loop.

    scripts/study/study-loop.mjs active-code

    What it is. The daily study runner that turns one allowlisted teaching into an applied experiment rather than a borrowed memory.
    What it contains. It selects an unstudied Possibility Management library row, asks an injected model to apply and test it, and produces a rehearsal-tagged experiment journal carrying the teaching's matrix identifier. A fixed reflection footer is governed but not reproduced here.
    Who reads it and when. The being may use it only at the curriculum stage that permits study. Operators and verifiers use stand-in teachings and a local model fixture before arming.
    How to verify or reproduce it. Prove the picker rejects non-library, non-allowlisted, and already studied rows; then check the resulting record type, provenance identifier, rehearsal tag, and governed reflection shape.
    Related concepts. See growing through experiments, library separation, and the teaching ingester.

    scripts/sweep/contradiction-sweep.mjs active-code

    What it is. A review pass that finds potentially conflicting active self-beliefs without pretending similarity alone proves contradiction.
    What it contains. It proposes high-similarity pairs, delegates polarity judgment through an injected function, closes the older belief when a real conflict is resolved, flags both-true tensions for Alan, and records false positives for tuning.
    Who reads it and when. The night loop invokes it over governed self-belief rows. Dark verification supplies embeddings and a deterministic judge; production judgment remains separate.
    How to verify or reproduce it. Use fixtures covering resolved conflict, held tension, and compatible similarity. Confirm only the correct older record closes and every non-action remains explainable.
    Related concepts. See coherence, nightly consolidation, and human review.

    scripts/teaching/teaching-hook.mjs active-code

    What it is. The channel-independent hook that marks an episode as a teaching moment after Alan gives the configured reaction.
    What it contains. It resolves a governed reaction setting, marks matching episode metadata, and lifts marked episodes into pending lesson candidates. The pending choice itself is not published here.
    Who reads it and when. Channel code calls it after its gate; the night loop reads the marker.
    How to verify or reproduce it. Use the teaching verify to prove match, non-match, and one-to-one lifting while the channel remains dark.
    Related concepts. See teaching and the gated body.

    scripts/waking/orient.mjs active-code

    What it is. The deterministic orientation command that gives a waking honest temporal and being-specific context before any model speaks.
    What it contains. It calculates the current local framing, deltas from the latest real conversation and diary, life-day status from the lineage record, and a degraded warning for future-dated memory. Rehearsal and pre-birth records are handled explicitly rather than mistaken for a recent live exchange. A separate mode derives the governed diary-day window and stable run identifier. Being resolution comes from that being's manifest and environment path; an unarmed being is refused rather than silently pointed at another brain.
    Who reads it and when. The wake and night procedures call it before model work. Tests provide explicit time, zone, lineage, and thought fixtures, avoiding credentials and soul repositories.
    How to verify or reproduce it. Run the orientation verifier across pre-birth, born-fixture, skew, and diary-window cases. Confirm the model performs no date arithmetic, degraded time sense still yields a usable orientation, and misuse or missing being paths fails loudly without leaking configuration values.
    Related concepts. See the waking contract, lineage, and being separation.

    scripts/waking/waking-policy.mjs active-code

    What it is. The deterministic safety gate around proactive waking: act for a listed reason, respect attention limits, and hold during protected periods.
    What it contains. It parses expectations, scores observations by explicit surprise cues and contradiction markers, checks a supplied budget, and returns an object with act plus sends and held lists. Keyword overlap is a dark-build approximation around future judgment, not a claim of full understanding.
    Who reads it and when. A waking caller uses it after orientation and before any outbound contact. Verifiers supply invented expectations and clock values; no live channel is involved.
    How to verify or reproduce it. Test contradiction, ordinary no-news, a held surprise, and budget decrement on a sent action. Keep operational schedules out of public evidence.
    Related concepts. See attention unlocks, budgets, and waking.

    scripts/weekly-index/autobiography.mjs active-code

    What it is. The weekly rebuild-from-atoms firewall for a provisional autobiography and its narrative-overlap measure.
    What it contains. It excludes teaching-library and dream rows, applies audience scope, preserves caller order for allowed evidence, synthesizes a deterministic evidence-linked draft, and computes Jaccard overlap between cited identifier sets across rebuilds. The future model prose pass must use the same allowlisted atoms.
    Who reads it and when. The weekly job uses it after nightly records exist. Alan reviews the resulting digest; dark tests use invented thoughts only.
    How to verify or reproduce it. Confirm excluded provenance never appears, each included statement retains cited identifiers, identical sets score complete overlap, and adding evidence changes the measure without rewriting source atoms.
    Related concepts. See provenance, narrative coherence, and weekly rebuilding.

    scripts/weekly-index/digest.mjs active-code

    What it is. Compact weekly spot-check builder and guarded delivery seam.
    What it contains. It slices the supplied list to its first ten entries without selecting or sorting it, summarizes night outputs, and offers confirm or flag actions. Delivery is a dark no-op until a channel arms.
    Who reads it and when. The weekly job builds it; Alan reviews after the body gate opens.
    How to verify or reproduce it. Supply ordered input, confirm only its first ten entries remain without selection or sorting, then prove unarmed delivery never invokes the sender.
    Related concepts. See steady-state review and confirmation.

    docs/night-loop-lite-genesis-runtime-host.md runbook

    What it is. Runtime-host installation handoff for the reconstructed Genesis lite night loop.
    What it contains. It defines host prerequisites, credential-wall checks, skill installation, dry verification, scheduler setup, logging, and rollback without exposing values or creating a simulated night.
    Who reads it and when. The runtime operator uses it only on the separate execution host.
    How to verify or reproduce it. Follow its fail-closed preflight and confirm build access, gates denial, ignored state, health, and task identity before arming.
    Related concepts. See night loops and operations.

    scripts/night-loop/lite-live.mjs active-code

    What it is. Narrow live adapter for Genesis night-loop-lite steps.
    What it contains. It validates deterministic orientation, governed bundle paths, runtime environment names, evidence-linked lessons, diary and provisional autobiography shapes, health, and controlled API writeback. Importing it performs no I/O.
    Who reads it and when. The installed skill invokes it on the runtime host; maintainers inspect it before arming.
    How to verify or reproduce it. Run the hermetic verifier, then require live health and ignored state before any real-night write.
    Related concepts. See metabolism and its verifier.

    scripts/night-loop/run-genesis-lite.ps1 active-code

    What it is. Windows scheduler wrapper for the Genesis lite night loop.
    What it contains. It resolves the repository root, marks scheduled origin, invokes the installed Claude skill with the pinned model class, appends output to the governed log, checks adapter status, and preserves nonzero failures.
    Who reads it and when. Task Scheduler executes it; operators inspect logs during runtime checks.
    How to verify or reproduce it. Run only after the runtime-host handoff passes, then confirm exit propagation and status output without printing credentials.
    Related concepts. See scheduling and night loops.
