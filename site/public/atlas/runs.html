    Atlas: runs/

    TLDR

    The runs directory is an audit trail of planning and co-evolution work. Six readable reports capture evolved plans, adversarial findings, temporal analysis, and this site's execution handoff. Three co-evolution bundles preserve the input, prompts, raw responses, cleaned passes, working copy, state, and diagnostics for a repeatable two-pass review pipeline. These are historical artifacts, not current design authority.

    What this page covers

    Use run artifacts to reconstruct how a decision or document revision was produced. The compact entries share one pipeline anatomy but identify every stage separately, so a reviewer can distinguish original input from prompts, model output, cleaned text, mutable assembly, state, and logs. Machine path fragments in archive filenames are historical labels only and are not operational instructions.

    File entries

    runs/GROWING-evolved.md

    archive
    What it is. The evolved candidate of the developmental plan produced by the document review pipeline.
    What it contains. A revised full-document proposal that incorporates adversarial and compositional passes while preserving the raising-not-building frame.
    Who reads it and when. Design reviewers consult it to understand proposed changes and their lineage.
    How to verify or reproduce it. Diff it against GROWING-EDGEWEAVER.md and the run bundle, then treat only merged authority text as binding. Review status language against the implementation ledger so prepared, dark, partial, pending, and live states remain distinct.
    Related concepts. See sources and method, reproduction, and governance.

    runs/PLAN-evolved.md

    archive
    What it is. The evolved candidate of the Genesis system plan produced by the review pipeline.
    What it contains. Task context and a revised plan proposal assembled from multi-pass critique.
    Who reads it and when. Design reviewers use it to trace how proposed architecture changes were formed.
    How to verify or reproduce it. Diff it against PLAN.md, inspect source-pass evidence, and never let archive status override the committed authority. Review status language against the implementation ledger so prepared, dark, partial, pending, and live states remain distinct. Treat any contradiction with higher-authority design as a decision-log issue, not permission to choose whichever instruction is easier.
    Related concepts. See sources and method, reproduction, and governance.
